2. GÉNÉRALISATION DU PARSEUR

Les contraintes suivantes ont été supprimées du moteur général :

- exactement 120 lignes ;
- exactement trois colonnes ;
- exactement 40 lignes par colonne ;
- exactement trois paragraphes modernisés ;
- liste codée en dur des trois dimensions d’images ;
- empreinte SHA-256 codée en dur dans le parseur.

Ces valeurs subsistent uniquement dans la suite de non-régression du prototype v0.4.

Le parseur accepte maintenant :

- un nombre quelconque de folios ;
- un nombre quelconque de colonnes par folio ;
- un nombre variable de lignes par colonne ;
- des lignes contenues dans des éléments l ;
- des lignes introduites par des jalons lb, y compris dans un conteneur TEI ;
- zéro, un ou plusieurs paragraphes modernisés par unité ;
- l’absence totale de couche modernisée pour une colonne ;
- des références de fac-similé portées par pb, cb, l ou lb ;
- des zones TEI internes référencées par facs="#identifiant" ;
- des fragments d’image de forme #xywh=.

L’ordre des folios, colonnes, lignes, jalons et contenus est dérivé de l’ordre documentaire du TEI. Aucune unité textuelle n’est triée ou reconstruite depuis un nombre attendu.

Lorsqu’une couche modernisée manque, le modèle conserve un tableau vide. Le lecteur affiche alors l’indication explicite :

« Aucune couche modernisée n’est fournie par le TEI pour cette colonne. »

Aucun texte modernisé n’est généré automatiquement.

4. VALIDATION TEI

Schéma Relax NG ajouté :

C:\Corpus Scriptura\bible-patristique\data\manuscrits\bible-899\schema\bible899-subset.rng

Une validation TypeScript équivalente, plus précise pour les messages de contrôle, est exécutée par les tests, la génération du manifeste, l’import et la compilation.

Les validations couvrent notamment :

- présence simultanée de abbr et expan dans chaque choice ;
- présence de reason ou cause dans chaque gap ;
- contenu identifiable de chaque unclear ;
- xml:id stable sur chaque ligne l ou lb ;
- unicité des identifiants de lignes ;
- unicité globale des xml:id ;
- valeurs admises de break ;
- conservation fonctionnelle de break="no" ;
- existence des zones TEI référencées ;
- existence réelle de chaque image utilisée.

Les erreurs indiquent le chemin du fichier et, selon l’unité concernée, le folio, la colonne, le numéro de ligne et le xml:id.

Le schéma Relax NG a été vérifié avec lxml. Les fichiers suivants sont conformes :

- Bible_899_master.xml ;
- single-column.xml ;
- multiple-folios.xml ;
- milestone-lines.xml ;
- zone-reference.xml.


5. FAC-SIMILÉS ET COORDONNÉES

Chaque colonne et chaque ligne peut maintenant recevoir une ou plusieurs références de fac-similé.

Le moteur prend en charge :

- une image complète ;
- une zone définie dans un surface TEI ;
- un fragment xywh ;
- l’héritage d’une image déclarée au niveau du folio ou de la colonne ;
- l’absence temporaire de coordonnées.

Aucune coordonnée n’a été inventée pour les trois images actuelles.

Les unités actuelles sans coordonnées détaillées sont signalées dans les données de contrôle :

- 1r_a ;
- 1r_b ;
- 1v_a.

Le lecteur continue à afficher les trois images actuelles et précise que les coordonnées détaillées ne sont pas renseignées.


6. NAVIGATION DU LECTEUR

Le lecteur construit maintenant sa navigation depuis les folios et colonnes réellement produits par le parseur.

La navigation permet :

- de sélectionner un folio dans une liste générée depuis le TEI ;
- d’aller au folio précédent ;
- d’aller au folio suivant ;
- de sélectionner une colonne précise du folio courant.

Une seule colonne est affichée à la fois. Le nombre de lignes indiqué dans son en-tête est calculé depuis le TEI et n’est plus fixé à 40.

Les trois modes sont conservés :

- diplomatique ;
- abréviations développées ;
- graphie modernisée.

Le fonctionnement responsive existant est conservé. La navigation se réorganise sur petit écran.

Avant un import, les images référencées doivent être placées dans :

C:\Corpus Scriptura\bible-patristique\public\manuscrits\bible-899

Commande d’import ou de remplacement :

Set-Location 'C:\Corpus Scriptura\bible-patristique'
& 'C:\Program Files\nodejs\npm.cmd' run bible899:import -- 'C:\chemin\vers\le-nouveau-lot.xml'

La commande réalise automatiquement :

1. la lecture du fichier candidat sans transformation ;
2. sa validation XML et TEI ;
3. la vérification des identifiants, abréviations, lacunes et lectures incertaines ;
4. la vérification de toutes les images ;
5. la copie octet pour octet vers le chemin maître stable ;
6. le calcul de l’empreinte ;
7. la régénération du manifeste ;
8. l’exécution de tous les tests ;
9. la compilation de production du site.

Si les tests ou la compilation échouent, le TEI maître et le manifeste précédents sont restaurés.

Cette commande ne corrige, ne modernise et ne réécrit jamais le texte du TEI.

Aucun nouveau lot ni nouveau folio n’a été importé pendant cette phase.
